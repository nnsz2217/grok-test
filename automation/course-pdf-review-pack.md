# 用 Power Automate 桌面版把多份课程 PDF 合成复习包

把同一门课的若干份 PDF 讲义，按顺序合并成一个复习用 PDF。本篇面向在 Windows 上、不想写代码的大学生，只用官方「合并 PDF 文件」操作。不需要 Google 帐户，也不需要 API Key。

## 正文

### 能解决什么问题

复习时常常要把第 1 讲、第 2 讲、第 3 讲等多份 PDF 逐个打开。本流程把「取出投放文件夹里的 PDF → 合并成一份新文件，写到输出文件夹」做成一条可反复运行的桌面流。合并结果是一份**新的** PDF，原件应保留，不要把输出路径写成某一份源文件本身。

它能做的是：把已经准备好的若干份 PDF 合成一份。它不能做的是：根据讲义内容自动排课序，也不能保证书签、目录或复杂版式在合并后原样保留。个人 Microsoft 帐户同样不能把这条流接到云端，做「文件一出现就立即合并」。

### 需要哪些工具

- 一台符合官方系统要求的 Windows 10 或 Windows 11 电脑（家庭版即可在本地有人参与运行）。不支持 ARM 处理器设备。
- Power Automate 桌面版。Windows 11 可能已预装；若没有，可从 [Microsoft Store](https://apps.microsoft.com/detail/9NFTCH6J7FHV) 安装。用个人 Microsoft 帐户登录即可。
- 不需要 API Key，不需要 Google 帐户，也不需要另外购买 PDF 软件。

安装、登录和「个人帐户没有云端触发」的说明，与 [用 Power Automate 桌面版自动归档课程资料](course-material-auto-filing.md) 相同，本篇不重复展开。

### 触发条件

与课程资料归档相同：个人 Microsoft 帐户只能在本机手动运行，或在手动跑通以后，再按官方文档用任务计划程序、运行 URL 定期启动。这是「到点检查一次」，不是实时监视。本次实测只覆盖了在设计器里点「运行」。

### 完整工作流程

**约定（动手前先做完）**

- **投放文件夹**：只放要合并的课程 PDF，例如 `复习包投放`。在资源管理器地址栏复制完整路径。不要把无关 PDF 放进去。
- **输出文件夹**：另建一个文件夹，例如 `复习包输出`。合并后的文件必须写到这里，**不要**写回投放文件夹里某一份源 PDF 的路径，以免覆盖原件。
- **输出文件名**：例如 `高数复习包.pdf`。第一次测试建议用带「测试」字样的文件名。
- **页序**：合并后的页序取决于「获取文件夹中的文件」取出列表的顺序。不要默认「按文件名看起来会从第 1 讲排到第 3 讲」——本次实测里，即使设置了按文件名排序，得到的页序仍是第 3 讲、第 2 讲、第 1 讲。若你必须按讲次排列，先在投放文件夹里检查结果，必要时改名（例如改成 `01`、`02`、`03` 前缀）再跑一次，并打开合并结果确认页序。

**在设计器里搭流（全部使用预生成操作）**

1. 启动 Power Automate，在控制台选择「新建流」，输入名称（例如「课程PDF复习包」），选择「创建」。
2. （建议）用「如果文件夹存在」，条件选「不存在」，检查输出文件夹；在分支里用「创建文件夹」把它建出来。
3. 添加「获取文件夹中的文件」：
   - 文件夹：投放文件夹的完整路径；
   - 文件筛选器：`*.pdf`；
   - 包含子文件夹：关闭；
   - 可尝试将「排序方式」设为名称、升序，但本次实测不能把它当成已经可靠的页序保证。
4. 添加「合并 PDF 文件」：
   - 要合并的 PDF 文件：上一步得到的文件列表变量；
   - 合并后的 PDF 路径：输出文件夹加上新文件名，例如 `C:\Users\你的用户名\Desktop\复习包输出\高数复习包.pdf`；
   - 「如果文件存在」：测试阶段可用「覆盖」，这样重复跑同一测试不会因旧的测试文件而失败。处理正式复习包时，若不想覆盖已有复习包，应改成「不执行任何操作」并换一个新文件名。
5. 保存后，在设计器或控制台运行一次，按下面的「怎样算做完」检查。

### 是否需要 API Key

不需要。

### 使用成本

与课程资料归档相同：官方写明利用 Microsoft 帐户使用 Power Automate 无需额外费用。核对日期：2026-11-25（Asia/Shanghai）。本次实测费用为 0。

### 技术门槛

不需要编程。需要会复制文件夹完整路径，在设计器里填写「获取文件夹中的文件」和「合并 PDF 文件」，并在运行后打开合并结果检查页数和页序。

### 适用场景

- 同一门课有多份 PDF 讲义或习题，希望合成一份便于复习或打印的文件。
- 使用个人 Windows 电脑和个人 Microsoft 帐户，只在本机运行。
- 没有 Google 帐户，或不想再装其它 PDF 工具。

不适用：必须按讲次严格排序却又不愿意在合并后人工检查；需要保留原 PDF 书签或复杂交互；需要文件一放入文件夹就立刻在云端合并。

### 潜在限制和安全风险

- **可能覆盖输出文件**。如果把合并路径写成某一份源 PDF，或输出文件夹里已有同名文件且选项为「覆盖」，原件或旧复习包会被替换。务必把输出路径和投放文件夹分开。
- **页序不一定按文件名递增**。本次实测见「实测记录」。合并后必须打开文件看一眼页序。
- **书签与版式**：官方能力是合并 PDF 页面。本次测试文件是单页示意图，没有书签，故未核对书签是否保留。
- **不是实时监视**；需要本机已登录、有人参与运行；一次只能跑一条本地有人参与的流。
- 只处理你自己准备好的课程副本，不要把含个人隐私或未确认来源的 PDF 送去合并。

### 实测记录（2026-11-25，Asia/Shanghai）

- **对象**：桌面流「课程PDF复习包」。目的是把三份高数讲义测试 PDF 合并成一份复习包，且不覆盖源文件。
- **环境**：与课程资料归档通测同一台电脑、同一个 Microsoft Store 版 Power Automate 1.0.2164.0、同一个个人 Microsoft 帐户。在设计器里点「运行」。
- **测试材料**：隔离文件夹 `PAD自动化测试副本\复习包投放` 中预先放入 `高数-第1讲-测试.pdf`、`高数-第2讲-测试.pdf`、`高数-第3讲-测试.pdf`（各 1 页 A4 示意图，不是正式课件）；输出目录 `PAD自动化测试副本\复习包输出` 事先只有说明用文本。
- **实际操作**：流中先确保输出文件夹存在，再用 `*.pdf` 获取投放文件夹中的文件（脚本里设置了按文件名、升序），最后用官方「合并 PDF 文件」输出到 `复习包输出\高数复习包-测试.pdf`，「如果文件存在」为「覆盖」。2026-11-25 20:11:45（Asia/Shanghai）从设计器点「运行」，20:11:47 生成输出文件，20:11:48 状态回到「就绪」，约 3 秒。
- **结果**：输出文件 `高数复习包-测试.pdf` 已生成，大小 204,140 字节，共 3 页，页面尺寸为 A4。投放文件夹中三份源 PDF 的大小和修改时间均未改变，没有被覆盖。费用为 0。
- **页序问题**：打开合并结果后，第 1 页是「高等数学 第3讲」，第 2 页是「第2讲」，第 3 页是「第1讲」，与文件名 1、2、3 的预期顺序相反。因此「按文件名升序就能得到讲次顺序」在本次环境中**不能**标为已核对。
- **人工介入**：登录需要本人完成。从设计器运行时没有再点确认。
- **评价**：合并本身成功，源文件安全，评为 B。扣分原因是页序与预期相反，正式使用前必须打开结果检查顺序。

### 怎样算做完

1. Power Automate 桌面版已安装并已用个人 Microsoft 帐户登录。
2. 投放文件夹和输出文件夹路径已写进流里，输出路径不是任何一份源 PDF。
3. 控制台里能看到已保存的流（例如「课程PDF复习包」），其中包含「获取文件夹中的文件」和「合并 PDF 文件」。
4. **用副本做通测**：投放文件夹中放入至少两份测试 PDF，运行该流后，输出文件夹出现新的合并 PDF，源文件仍在且未被改短或替换。打开合并结果，确认页数等于各源文件页数之和，并核对该页序是否符合你的讲次需要。
