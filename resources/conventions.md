# 笔记约定

以后写进这个仓库的每一篇主题笔记，都要让以后的自己判断三件事：这句话从哪来、什么时候核对过、能不能当事实用。各分类的 `README.md` 用同一套元数据，并写明本页是索引。

## 每篇笔记必填

放在文末的「元数据」一节。缺任何一项，就先不要合并。

- **来源链接。** 直接链到原始材料：官方文档、仓库、论文、产品页面，或你核对过的文章。转述不能代替链接。一条主张对得上至少一处来源；对不上就删掉，或标成待核实。
- **更新时间。** 最后一次核对内容的日期，时区写明 Asia/Shanghai，格式为 `YYYY-MM-DD（Asia/Shanghai）`。改了事实就更新日期；只改错字也更新日期，避免把旧核对当成新核对。
- **信息可信度。** 用短标签说明核对到哪一步。可选用：
  - `已核对`：文中事实已对照来源链接核过，日期就是更新时间。
  - `部分核对`：写明哪些已核对、哪些没有。
  - `待核实`：只是收集，还不能当事实引用。
  - `结构规划已核对；分类内容待后续研究补充`：用于尚未写入研究的索引页。

## 适用时再写

不知道就写「未知」或「不适用」。不要填一个看起来合理的数字或结论。

- **平台。** 笔记依赖的产品或运行环境。跨平台时只列出已经核对过的那些。还没测过的，不要写成兼容。
- **技能门槛。** 读这篇之前需要会什么。写成具体能力，例如「会改一个 Markdown 文件并提交 Pull Request」。
- **费用。** 只写从来源里能核对到的档位：`免费`、`付费`、`API 计费`，或它们的组合。价格、配额和套餐名会变；要写进正文时，必须同时带来源和更新时间。索引页和「尚未检索」清单里不写价格。

## 文件怎么放

- 同一主题已经有文件时，改那个文件，不要另开一篇平行笔记。
- 只有独立的新主题才新建文件。新建之后，更新所在分类的 `README.md`：在「当前内容」里加上相对链接，并用一两句说明这篇覆盖什么。
- 根目录的 `ai-skill-engineering-guide.md` 留在原处。需要引用时只放链接，不复制到 `skills/` 或其他目录。
- 研究按批次入库。一个 Pull Request 只放入这一批真正核对过的笔记。还没写的主题留在索引的「尚未检索、尚未核实」清单里。
- 变更通过 Pull Request 进入 `main`。不要直接推送到 `main`。

```markdown
<这篇解决什么问题。>

<只写能对上来源的内容。>

- 来源：<链接>
- 信息可信度：<已核对 / 部分核对 / 待核实>
- 平台：<如适用；否则写不适用>
- 技能门槛：<如适用；否则写不适用>
- 费用：<免费 / 付费 / API 计费 / 未知 / 不适用>
```
